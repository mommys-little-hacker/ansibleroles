# Линтинг ansible-кода

Используй этот скилл для проверки кода `ansible-lint`: до коммита, после правок
ролей и плейбуков, а также по явному запросу пользователя.

Скилл выполняет минимально необходимый список действий: активацию virtualenv
и запуск `ansible-lint`. Создание окружения и установку зависимостей
(включая сам `ansible-lint` из `requirements.txt`) этот скилл не выполняет -
для этого используй скилл `ansible-setup`.

## Предусловия

- Рабочая директория - корень репозитория.
- Виртуальное окружение - папка `.ansibleroles` в корне репозитория.
- `ansible-lint` входит в `requirements.txt`, поэтому доступен после
  выполнения скилла `ansible-setup`; отдельно устанавливать его не нужно.
- Конфигурация ansible (`ansible.cfg`) в корне репозитория используется
  автоматически; файл vault-пароля `.vaultpass` также подхватывается из
  `ansible.cfg`, передавать `--vault-password-file` не нужно.
- Кастомная конфигурация линтера отсутствует - применяется набор правил по
  умолчанию; путь для кастомной конфигурации - `.config/ansible-lint.yml`.

## Порядок действий

### 1. Проверить и активировать virtualenv

```sh
source .ansibleroles/bin/activate
```

Если `.ansibleroles/bin/activate` отсутствует - сначала выполни скилл
`ansible-setup` (создание окружения и установка зависимостей), затем
активируй virtualenv и продолжи линтинг.

### 2. Запустить ansible-lint

По умолчанию линтится весь проект (плейбуки в корне репозитория и роли):

```sh
ansible-lint
```

Можно ограничить проверку конкретными файлами и каталогами:

```sh
ansible-lint mcp.yml            # конкретный плейбук
ansible-lint roles/<name>/      # конкретная роль
```

Полезные флаги:

```sh
ansible-lint --list-rules       # список правил с описаниями
ansible-lint -x yaml,lint       # пропустить теги правил
```

### 3. Обработать результаты

- Исправление замечаний в коде - обычная работа над задачей: чини только
  то, что относится к текущей задаче. Замечания вне её рамок - перечисли
  пользователю, не исправляя самостоятельно.
- Если замечание ложное и для его подавления нужна кастомная конфигурация
  (`.config/ansible-lint.yml`, `# ansible-lint: disable` и т.п.) -
  сообщи пользователю и внеси правки только после его явного согласия.
- Ошибки вида "модуль не найден", "коллекция не найдена" - это ошибки
  окружения: выполни скилл `ansible-setup`, затем повтори линтинг.

## Ограничения

- Не запускать `ansible-lint` напрямую из системного окружения - только
  через активированный `.ansibleroles`.
- Не устанавливать и не обновлять `ansible-lint` в рамках линтинга:
  версия зафиксирована в `requirements.txt`, предложение инструмента
  обновиться игнорировать.
- Не создавать и не править `.config/ansible-lint.yml` и inline-подавления
  (`# ansible-lint: disable`) без явного запроса пользователя.
- Флаг `--fix` применять только по явному запросу пользователя; после
  автофикса показать пользователю изменения через `git diff`.
- Не расшифровывать vault-файлы ради линтинга: `ansible-lint` пропускает
  зашифрованные файлы сам, выводить их содержимое не требуется.
- Не править `requirements.txt`, `ansible.cfg` и `.vaultpass` в рамках
  линтинга: если нужен новый пакет или изменение конфигурации - сообщить
  пользователю.
