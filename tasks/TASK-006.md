# TASK-006: Исправить ошибки ansible-lint в роли certbot

**Создана:** 2026-10-29 (PM: opencode)
**Взята в работу:** -
**Завершена:** -

## Описание
Устранить замечания `ansible-lint` в роли `certbot`: форматирование YAML-комментариев, длину строк, jinja-пробелы, `ignore-errors` → `failed_when`, `no-changed-when` и устаревшие noqa-теги 301/305.

## ТЗ/Требования
- `yaml[comments]` (`roles/certbot/defaults/main.yml`, 9 мест): добавить пробел после `#` во всех комментариях без пробела.
- `yaml[line-length]` (по 3 строки в каждом из `tasks/cloudflare.yml`, `tasks/route53.yml`, `tasks/standalone.yml`, `tasks/webroot.yml`): перенести строки > 120 символов без изменения смысла команд (это многострочные `job:` в cron-задачах — переносы внутри folded-скаляров `>` безопасны, проверить итоговую строку команды).
- `jinja[spacing]` (по 1 в каждом из указанных файлов + `tasks/standalone.yml:17`): поправить пробелы в Jinja-выражениях: `{%endfor%}` → `{% endfor %}` и аналогично по рекомендациям линтера. Внимание: шаблоны формируют командную строку certbot — после правки сравнить итоговую команду до/после (пробелы внутри цикла `-d domain` должны сохраниться).
- `ignore-errors` + `no-changed-when` (`tasks/standalone.yml`, задачи «Run pre hook» и «Run post hook»): заменить `ignore_errors: true` на `failed_when` с явным условием допустимого отказа. **Решение владельца (2026-10-29): выбран вариант «мягкий» — сбои hook'ов не должны прерывать выпуск сертификата; текущее поведение сохранить.** Реализация: зарегистрировать результат (`register`) и указать `failed_when: false` (явная форма допустимости любого исхода, эквивалент текущего `ignore_errors: true`, но без замечания линтера). Добавить `changed_when: false` для этих `command`-задач (hook'и не меняют состояние, которым управляет Ansible). Если в будущем понадобится селективная обработка кодов возврата — вернуться к вопросу.
- `no-changed-when`: проверять, что задачи с `command`/`shell` имеют `changed_when`/`creates`, где применимо.
- `warning[outdated-tag]` (`tasks/route53.yml:17`, `# noqa 301 305`): заменить устаревшие номера на имена правил: `# noqa no-changed-when command-instead-of-shell` (та же замена требуется в аналогичном комментарии в `tasks/standalone.yml:8`, если линтер начнёт ругаться на старые теги там — фактически там noqa уже в старом формате).
- Логику выпуска сертификатов не менять.
- Прогнать `./scripts/lint.sh` — по роли `certbot` замечаний быть не должно.

## Тест-кейсы
1. `ansible-lint roles/certbot/` завершается без ошибок и предупреждений (включая `warning[outdated-tag]`).
2. Синтезированная cron-команда renew (задача «Set up certificate renewal») идентична до/после правок переносов строк (проверить на тестовом инвентаре через `--check --diff` или глазами в `certbot renew --dry-run`).
3. Команда выпуска сертификата (certonly) после правок jinja-пробелов идентична исходной (побайтово, кроме выравнивания).
4. При несуществующем pre/post hook (переменные не определены) задачи пропускаются; при падении hook-команды задача ведёт себя согласно согласованному `failed_when` (не валит плейбук на ожидаемых кодах возврата).
5. Повторный прогон роли идемпотентен: cron-задачи не дублируются, certbot не перезапускается без необходимости.
6. `./scripts/lint.sh` не возвращает новых замечаний по сравнению с базовой линией.
