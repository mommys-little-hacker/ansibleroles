# Гайдлайны разработки

Краткие инструкции для агентов разработки. Используйте ссылки на специфичные гайдлайны вместо чтения кода.

## Иерархия гайдлайнов

Каждый компонент проекта *может* иметь свои гайдлайны, перед началом работы проверь их наличие и прочитай их, от корневого (этого), до наиболее вложенного, включая промежуточные. Чем больше уровень вложенности гайдлайнов - тем выше их приоритет. Если гайдлайнов на текущем уровне нет - используй вышестоящие.

**Пример**:
- `/DEV_GUIDELINES.md` <- Общие гайдлайны всего проекта, самый низкий приоритет
- `/roles/DEV_GUIDELINES.md` <- Гайдлайны для написания ролей, приоритетны над Общими
- `/roles/basic/DEV_GUIDELINES.md` <- Гайдлайны для конкретной роли, наивысший приоритет

Таким образом, если задача звучит как доработать "Доработать роль basic", то ты должен прочитать следующие гайдлайны в следующем порядке:
- `/DEV_GUIDELINES.md`
- `/roles/DEV_GUIDELINES.md`
- `/roles/basic/DEV_GUIDELINES.md`

## Структура проекта

- `./roles/` - Роли Ansible → [DEV_GUIDELINES.md](./roles/DEV_GUIDELINES.md)
- `./spec/` - ТЗ и спецификации
